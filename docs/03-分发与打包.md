# 分发与打包

> 目标：让感兴趣的观众拿到之后，填个 Key、扫个码就能用。
> 现实：技术能做到，但**签名成本和合规风险比技术本身更关键**。

---

## 先说结论

| 方案 | 观众要做什么 | 你要付出什么 | 推荐度 |
|---|---|---|---|
| **A. 源码 + 一键脚本** | 装 Node、跑 2 条命令 | 无 | ⭐⭐⭐ 先这样 |
| **B. Electron 安装包** | 双击 .dmg / .exe | 每年 $99 证书 + 持续维护 | ⭐⭐ 有余力再说 |
| **C. 托管成网页服务** | 打开网址注册 | 服务器成本 + 法律风险最大 | ⭐ 不建议 |

**建议先走 A，跑通 20-30 个人之后再考虑 B。** 因为现在还不确定功能会长成什么样，过早打包会让每次改动都变重。

---

## 方案 A：源码 + 一键脚本

现在唯一缺的就是「观众不用懂命令」。

再补一个 `安装.command`（macOS）/ `安装.bat`（Windows），做这几件事：

1. 检查有没有 Node，没有就提示装（或自带一个便携版 Node）
2. `npm install`
3. 启动服务并打开浏览器

观众的体感就是：**解压 → 双击 → 填 Key → 扫码 → 开用**。

优点：零成本、改动即时生效、出错能自己看日志。
缺点：仍要装 Node（可以打包便携 Node 绕过）。

## 方案 B：Electron 安装包

把 Next 服务塞进 Electron 里，做成一个真正的桌面 App。

### 结构

```
electron/
├─ main.js         启动内置 Next 服务 → 开窗口 → 退出时关服务
├─ preload.js
└─ package.json    electron-builder 配置
```

主进程要做的事：

```js
// 1. 起内置服务（端口随机，避免冲突）
spawn(nodeRuntime, ['node_modules/next/dist/bin/next', 'start', '-p', port])

// 2. 等端口可访问再开窗口
await waitForPort(port)
win.loadURL(`http://127.0.0.1:${port}`)

// 3. 退出时杀掉子进程，别留孤儿
app.on('before-quit', () => server.kill())
```

### 必须处理的三件事

**① 内置 Node 和 ffmpeg**
- Node：`electron-builder` 的 `extraResources` 放一份便携 Node
- ffmpeg：每个平台一份二进制（mac ~80MB，win ~70MB），放 `resources/`

**② 数据目录**
不能写进 App 包内（只读），要放：
- macOS: `~/Library/Application Support/CreatorConsole`
- Windows: `%APPDATA%\CreatorConsole`

现有的 `DATA_ROOT` 已经支持 `CONSOLE_DATA_DIR` 环境变量，App 启动时指过去即可。

**③ 代码签名（最大的坑）**

| 平台 | 不签名会怎样 | 签名成本 |
|---|---|---|
| macOS | 提示「无法验证开发者」，要右键→打开 才能运行 | Apple Developer $99/年 |
| Windows | SmartScreen 拦一次，点「仍要运行」即可 | 代码签名证书 $200-400/年 |

不买证书也能发，代价是每个用户都要多点两下、并信任你。**对一个免费小工具来说，这个代价可以接受**，在下载页写清楚步骤就行。

### 打包命令

```bash
npx electron-builder --mac --win
```

产物大约 150-200MB（Node + ffmpeg + Next 产物）。

## 方案 C：托管成网页服务（不建议）

看起来最省事，实际上问题最多：

1. **采集必须在用户本机跑** —— 抖音要真浏览器 + 真登录态，服务器上跑等于集中爬取，风控和合规风险极高
2. **登录态不能上传** —— 这是本项目的核心设计前提，托管就破坏了它
3. **成本** —— 每人的浏览器实例很贵

如果非要托管，唯一可行的形态是「**本机采集 + 云端展示**」：用户本地装个小程序负责采集，数据推到云端看板。复杂度和方案 B 差不多，但多了一份服务器账单。

---

## 合规风险（必须想清楚）

这个工具会以用户身份访问抖音网页、读取页面接口返回的数据。

| 风险 | 说明 | 缓解 |
|---|---|---|
| 违反平台用户协议 | 抖音 ToS 通常禁止自动化抓取 | 低频、只读、只采自己的数据，不做批量 |
| 账号被风控 | 高频操作可能触发验证码甚至限流 | 单并发、限速、屏幕外窗口、不做自动点赞评论 |
| 公开分发放大风险 | 用户越多，被平台注意的概率越高 | 小范围分享，不做公开推广 |
| 二次分发不可控 | 别人可能改造成爬虫工具 | 明确许可以及免责声明 |

**建议**：在小范围（比如粉丝群、私信）分享，README 里写明「仅供个人分析自己的账号使用」，
不要提供自动互动（点赞、评论、关注）功能——那会从「分析工具」变成「刷量工具」，性质完全不同。

---

## 我的建议路线

1. **现在**：补 `安装.command` / `安装.bat`，先让 macOS 观众能用
2. **跑一段时间**：看真实反馈，功能稳定了再打包
3. **要打包时**：先出 macOS 未签名版（右键打开），Windows 用 Portable exe 免安装
4. **有余力**：买 Apple 证书，做公证

每一步都能停下来，不用一次性投入。
