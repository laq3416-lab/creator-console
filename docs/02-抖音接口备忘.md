# 抖音创作者后台接口备忘

> 来源：2026-11-07 实测录制（`npm run collect:spy`），一个测试账号（7 粉 / 11 作品）。
> 平台随时会改，这份文档的价值是**改版时能快速比对哪里变了**。

---

## 0. 三条硬约束

| 约束 | 说明 |
|---|---|
| **必须开真窗口** | 无头模式访问抖音直接返回「验证码中间页」，实测确认。所有采集都走 `headless: false` |
| **不要逆向签名** | 前端请求带 `msToken` / `a_bogus` 等参数。我们的做法是**被动接收页面自己发出的请求**，不构造、不签名 |
| **aweme_id 不能用 number** | 7705251435105045786 超过 JS 安全整数（2^53），`JSON.parse` 后变 `...046000`。必须用 `aweme_list[].aweme_id` 这个**字符串**字段 |

## 2. 概览指标（11 项 × 每日）

```
GET /aweme/janus/creator/data/overview/all/?last_days_type=1
```

```jsonc
{
  "data": {
    "fans": {                     // 注意：这是「每日涨粉」，不是粉丝总数！
      "current_count": "19",
      "last_period_incr": "17",
      "option_list": [ { "date": "2026-10-31", "count": "1" }, ... ]
    },
    "play":    { ... },   // 每日播放
    "digg":    { ... },   // 每日点赞
    "comment": { ... },
    "share":   { ... },
    "profile": { ... },   // 主页访问
    "new_fans": { ... },  // 涨粉的子集（来源不同）
    "cancel_fans": { ... },
    "account_search": { ... },
    "post_search": { ... },
    "music_create": { ... }
  }
}
```

**踩过的坑**：`fans` 的 7 天数值相加 = 19，但账号真实粉丝只有 7，而 `cancel_fans` 全是 0。
用增量反推累计会算出负数。所以我们的策略是：

- `fans_gain` → 每日涨粉，如实存
- `fans` → 只存当前总数这一个点

前端拿到单点会显示「—」，不会画一条假曲线。

## 3. 作品列表（核心）

```
GET /janus/douyin/creator/pc/work_list?status=0&count=12&max_cursor=0
```

返回 `items[]`（含 metrics）和 `aweme_list[]`（含精确 ID 与时长），**两个数组要按 ID 对齐**。

```jsonc
// items[].metrics —— 25 个字段，全是字符串
{
  "view_count": "512",
  "like_count": "9",
  "comment_count": "0",
  "favorite_count": "3",        // 收藏
  "share_count": "0",
  "completion_rate": "0.003711",     // 完播率，0–1
  "completion_rate_5s": "0.186047",  // 5 秒完播
  "avg_view_second": "4.053667",     // 平均播放时长
  "avg_view_proportion": "0.033781",
  "bounce_rate_2s": "0.427549",      // 2 秒跳出率 ← 判断开头钩子的关键
  "fan_view_proportion": "0.001953",
  "homepage_visit_count": "0",
  "subscribe_count": "0",
  "unsubscribe_count": "0",
  "download_count": "0",
  "dislike_count": "0",
  ...
}
```

`aweme_list[].duration` 单位是**毫秒**（120000 = 120 秒）。

## 4. 平台自带的对比诊断（意外收获）

```
GET /janus/douyin/creator/data/diagnose/item_compare?item_id=<id>&selected_metric_count=2
```

抖音自己会挑 5 条"可比作品"回来，并给出当前作品与它们的指标对比（`compare_items` + `item.metrics`）。

**这意味着「爆款对标」这个功能，平台已经做了一半。** 我们的价值不在于重复它，而在于：

- 跨平台对比（平台只管自己站内）
- 用「超额系数」而不是绝对播放量排序
- 把对比结论翻译成动作

## 5.5 公开搜索（爆款雷达用）

```
GET https://www.douyin.com/search/<keyword>
→ /aweme/v1/web/general/search/single/
```

`data[]` 里每项含 `aweme_info`：作品的 `statistics` 和作者的 `follower_count`。

**注意三点**：
- 带上 `?type=video` 会切到 `/aweme/v1/web/search/item/` 并返回空数组，不要加
- `play_count` 恒为 0 —— 抖音公开页隐藏播放量，只能用点赞做基准
- 连续搜索会被节流，每个关键词要开新页面并 `bringToFront()`，否则后台标签页不发请求

## 6. 还没拿到的

- **私信**：走 `/aweme/v1/creator/im/user_token/` 拿 token，估计是 WebSocket 连接。需要单独研究，不是简单 XHR。
- **对标账号（别人的号）**：创作者后台只有自己的数据，别人的要回公开页采集，是另一条管道。

## 附：怎么重新录一次

```bash
cd app
npm run collect:login   # 扫码，登录态存 data/browser-profile
npm run collect:spy     # 自动翻页面 + 留 90 秒手动点，产物在 data/spy/
npm run collect         # 真正采集入库
```

`data/spy/raw/*.json` 里是原始响应，改解析器时对着它写，不用反复开浏览器。
